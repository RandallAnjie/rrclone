# 123 Pan

[123 Pan](https://www.123pan.com) (123云盘) is a Chinese cloud drive.
This backend uses its official **open platform API**
(`open-api.123pan.com`).

## Configuration

You need a developer app on the open platform:

1. Apply at <https://www.123pan.com/developer> with the account whose
   files you want to reach.
2. Note the app's `client_id` and `client_secret`.

```console
rclone config
```

```text
n) New remote
name> remote
Storage> 123pan
client_id> 0123456789abcdef
client_secret> *** (y to type it)
```

rclone gets access tokens with these credentials when it needs them
and keeps the current one in the config.

```console
rclone lsd remote:
```

## Hashes and modification times

123 Pan keeps an MD5 for every file, which rclone uses for checks. It
sets modification times itself, so rclone compares sizes, and MD5s with
`--checksum`.

Uploads need the MD5 up front. If the source can't supply one (for
example a local file is hashed as it's read, or a stream), rclone
copies the data to a temporary file first to hash it.

## Instant upload and server-side copy

When 123 Pan already has a file with the same MD5 and size anywhere,
an upload completes at once without sending the data. rclone uses this
for server-side copies, so `rclone copy remote:a remote:b` doesn't
download anything.

## Rate limits

The open platform limits each API to a few requests a second (for
example 1 a second for moves and renames, 3 for listings). rclone keeps
to these limits and retries when told it's going too fast, so big
folders take a while to list and many small moves are slow.

## Limitations

- Deleted files go to the 123 Pan trash.
- Names can't contain `\ / : * ? " < > |` or end in a space. rclone
  encodes these characters, see [encoding](/overview/#encoding).
- Modification times can't be set.
