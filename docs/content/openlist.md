# OpenList / AList

[OpenList](https://oplist.org) (and the [AList](https://alist.nn.ci)
it was forked from) mounts many cloud drives into one tree: 115, Aliyun
Drive, Baidu, Quark, Tianyi, China Mobile, Xunlei, local folders and
more. This backend talks to its native API (`/api`), so rclone reaches
every drive mounted in it through one remote.

This is usually better than OpenList's WebDAV: it uses the hashes the
drives provide, handles meta passwords, and waits for copies and moves
between drives, which OpenList runs as background tasks.

## Configuration

You need the URL of the site and one of:

- a user name and password (accounts with 2FA can't be used this way),
- the admin `token` from Settings → Other → Token, which doesn't expire
  but gives admin access, or
- nothing, if guest access is enabled.

```console
rclone config
```

```text
n) New remote
name> remote
Storage> openlist
url> https://alist.example.com
username> me
password> *** (y to type it)
```

Paths start at the top of your OpenList tree (your user's base path).
The first level is the mounts:

```console
rclone lsd remote:
rclone copy /photos remote:aliyun/photos
```

Session tokens expire (after 48 hours by default). rclone logs in again
when that happens.

Set `meta_password` for folders protected with a meta password.

## Modification times and hashes

Most drives behind OpenList ignore the modification time rclone uploads
with, so rclone doesn't trust the times by default and compares sizes
(and hashes with `--checksum`). If the storage keeps times, for example
local storage, set `preserve_mod_time = true` for normal syncs.

Hashes (MD5, SHA1, SHA256) are whatever the drive reports. A file with
no hash for a type just isn't checked by it. rclone sends the hashes it
knows with uploads, which lets some drives skip the upload entirely.

## Server-side copy and move

Within one mount OpenList copies and moves straight away. Between mounts
it runs a background task. rclone waits for the task, for up to
`task_timeout` (default 2 hours). Copies within one folder aren't
supported, so rclone downloads and uploads instead.

## Limitations

- Uploads stream through the OpenList server in one request and can't
  be resumed. A failed upload is retried from the start.
- The modification time can't be changed without uploading again.
- `rclone link` gives a signed `/d/` download link. It can't be revoked.
- There's no quota information, so `rclone about` isn't supported.
